# SESSION 09 — Advanced Autonomous AI Civilization & Collective Intelligence (owner spec, received 2026-11-21)

Gate rule: starts only after Session 08 passes. This is NOT a chatbot. Agents are functional only when they can: observe → decide → execute → change state → record outcomes → learn within defined limits. Never claim untested intelligence. Do not confuse LLM-generated text with autonomous intelligence.

Owner's architecture advice (standing): three intelligence tiers — (1) Simulation Intelligence: daily life, movement, work, sleep, travel, routine decisions; (2) Advanced Agent Intelligence: personal goals, business decisions, social relationships, complex situations; (3) Civilization Intelligence: government, economy, city management, international relations, large decisions. Do NOT run every human through AI APIs. External AI models are OPTIONAL enhancements, never mandatory dependencies; deterministic rules + lightweight algorithms for routine simulation; hybrid architecture with model invocation budgets.

## Central coordination (no competing engines)
ONE coordination architecture. Agent registry: identity, capabilities, permissions, memory, goals, execution states, communication, scheduling, performance monitoring. Support different agent classes (human, business, institution, city, government — most already exist as sim actors; register and coordinate them, don't rebuild them).

## Human upgrade (Session 01)
Observe environment → evaluate options → prioritise needs → plan → decide → execute → learn from outcomes → adapt future behaviour, consistent with individual characteristics + circumstances. (Session 01's decision engine is the base; this session adds planning + learning.)

## Long-term personal goals
Employment, education completion, family, home purchase, savings, business, skills, relocation. Each goal: priority, feasibility, required resources, timeline, dependencies, progress, completion conditions. Goals evolve from life events. (Extends character_goals.)

## Agent communication
Human↔human, human↔business, business↔business, citizen↔government, institution↔institution, city↔city, government↔government — respecting permissions + social relationships.

## Group decision-making
Community planning, business collaboration, organisational meetings, public consultations, government planning, scientific cooperation, emergency coordination. Outcomes emerge from individual preferences + available information + institutional rules.

## Business autonomy upgrade (Session 04)
Monitor demand, adjust inventory, recruit, manage production, negotiate suppliers, adjust prices, explore markets, invest capital, expand, respond to competition — always within financial capacity + resource constraints.

## Government intelligence upgrade (Session 05)
Monitor public conditions, identify problems, evaluate policies, allocate budgets, coordinate departments, respond to emergencies, measure policy outcomes, adjust development priorities, maintain institutional authority boundaries.

## City intelligence (Session 03)
Monitor population growth, housing demand, traffic congestion, water availability, energy demand, waste, employment, infrastructure capacity, environmental quality. Autonomous municipal planning recommendations + authorised actions.

## Environmental intelligence (Session 08)
Monitor changes, detect abnormal conditions, evaluate risks, recommend conservation, coordinate disaster preparation, evaluate recovery.

## Multi-level memory
Individual, family, organisational, institutional, community, historical civilization memory. Importance, retention, retrieval, experience evaluation, knowledge transfer, compression. Prevent uncontrolled growth. (Extends Session 01 memory + Session 02 generational history.)

## Decision architecture (configurable)
Every autonomous decision considers: current state, available information, objectives, resource constraints, possible actions, expected consequences, risk, decision priority, execution permissions. Decision + resulting world-state changes are recorded (decision_log pattern).

## Scenario evaluation / forecasting
Housing demand, business profitability, traffic congestion, resource shortages, population growth, economic instability, environmental risks — via transparent simulation models. Forecasts must be labelled and distinguished from actual outcomes.

## Coordinated emergency response
Detect events → assess severity → identify affected populations → request resources → coordinate transportation → contact institutions → monitor progress → support recovery. Human oversight maintained for high-impact PLATFORM-level actions.

## Structured negotiation
Employee↔employer, buyer↔seller, supplier↔manufacturer, citizens↔government, organisations↔institutions, governments↔international partners. Explicit objectives, constraints, offers, responses, outcomes.

## Learning (bounded)
Adapt from previous decisions, success/failure, social feedback, economic + educational + environmental + institutional experience. Learning modifies DEFINED behavioural parameters only. NO uncontrolled self-modification of executable code.

## Simulation orchestrator
Schedules agent updates, processes world events, resolves conflicting actions, manages dependencies, enforces permissions, coordinates subsystems, maintains consistent world state, monitors performance, recovers from failed tasks. Deterministic ordering where necessary; reproducible scenarios.

## Observability
Agent inspection: identity, current objectives, state, memory references, recent decisions, executed actions, failed actions, resource consumption, performance, decision explanations. Event timeline. Private simulated memories are not exposed to unauthorised observers where the platform implements access restrictions.

## Agent governance
Permissions, resource limits, action validation, decision auditing, execution timeouts, failure recovery, conflict resolution, simulation sandboxing, model invocation limits.

## Performance
Priority-based scheduling, event-driven processing, agent update batching, hierarchical simulation, decision caching where appropriate, memory retrieval optimisation, task queues, background processing, resource quotas, model invocation budgets. Do NOT call external LLMs for every agent action.

## Acceptance criteria (test-verified, measurable multi-agent runs)
1 Multiple autonomous agents operate. 2 Persistent agent identities. 3 Agents pursue goals. 4 Decisions produce actual actions. 5 Actions update world state. 6 Agents communicate. 7 Businesses decide autonomously. 8 Government responds intelligently. 9 Cities respond to changing conditions. 10 Memory retrieval works. 11 Learning changes future behaviour. 12 Negotiations produce valid outcomes. 13 Conflicting actions resolved. 14 Failed tasks recover safely. 15 Agent permissions enforced. 16 Performance remains acceptable (measured). 17 Previous sessions remain functional.
