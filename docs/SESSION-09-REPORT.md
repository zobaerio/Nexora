# NEXORA — Session 09 Report: Advanced Autonomous AI Civilization & Collective Intelligence

**Date:** 2026-11-21 · **Branch:** `feat/session09-agents` · **Layer:** `tools/sim/agents.py` (+ `agentsview.py`, `data/agents-config.json`)

## What this session is — and is not

Session 09 is a **coordination layer** over the actors Sessions 01–08 already built. It recreates nothing. Citizens already decided (S01), businesses already priced/hired/produced by recorded rules (S04), government already fired policies on measured triggers (S05), cities already computed pressure indicators (S03), and disasters already drew real responses (S08). What was missing — and what this session adds — is the unifying machinery the spec asks for: a registry over those actors, extended personal goals, one structured negotiation protocol, a closed assessment loop, multi-level memory with retrieval that provably changes a decision, transparent scored forecasts, disaster coordination tracking, bounded recorded learning, capability-gated permissions, conflict resolution with recorded losers, and an observatory CLI.

Per the owner's doctrine: three intelligence tiers (Simulation / Advanced Agent / Civilization), **never LLM-per-agent**, and in this environment **no external LLM calls at all** — every behaviour below is deterministic, seeded, and rule-based over measured state. This is not a chatbot. An agent here is functional only in the spec's sense: observe → decide → execute → change state → record outcome → learn within defined limits — and each claim below names the test that proves it.

**Access position (stated plainly):** the simulated agents' memories, goals and negotiation records are data inside a local simulation database. The `--agents` observatory reads that database on the owner's own machine. Nothing is transmitted anywhere; there is no external service, account, or API involved.

## Units

1. **Config** — `data/agents-config.json`: capabilities per class (only `government` holds `enact_policy`), negotiation bounds, goal parameters, forecast kinds/horizons, assessment thresholds, memory caps, supplier-reliability window, coordination overdue days. All rates labelled SIM MODEL in the file.
2. **Registry** — `agent_registry` is a view over real actors (citizen/business/institution/city/government/system), id `AG:<class>:<ref_id>`; sync refreshes status from the actor itself (death/closure → inactive). `agent_params` + `set_param` give every learned parameter a bounded, recorded home (every change writes an `agent_learning` row).
3. **Permissions** — `require_capability` gates the layer's own actions; a denial writes a failed `agent_actions` row and raises. `request_policy_action` routes an authorised request to the government agent as a message; enactment stays S05's machinery.
4. **Multi-level memory** — `agent_memories` at family / organisation / community / civilization levels, lifted monthly from real event tables (life events, business events, generational history, elections/crises/disasters), deduped by source ref, importance-ranked retrieval that counts accesses, bounded compression (oldest sub-threshold records merge into one `compressed_summary`; importance survives).
5. **Goals** — `character_goals` extended (priority, progress, feasibility, deadline, dependencies, completion rule) + `goal_progress_log`. Derived goals come from measured state only (unemployed → find_employment 80; enrolled → complete_education 70; renting + savings → own_house 65; ambitious + risk-tolerant + capital → open_business 60; employed → save_amount 55; below promotion bar → reach_skill 50). Progress is measured from real records for **all** active goals (genesis included); completion is by record; abandonment only for derived goals past deadline below the progress floor. Priority adaptation (±, bounded) is recorded learning. The top goal takes one real monthly step: a `banking.deposit` toward savings/home goals — a missing bank account is a recorded failed action, retried next month. **Retrieval proof:** a family memory of a household business closure, retrieved during derivation, cuts the derived open_business priority by exactly the configured 30 and records the risk in feasibility (unit-proven: 60 vs 30 on otherwise-identical citizens).
6. **Negotiation** — one real protocol where the architecture supports it: wage negotiation at hiring. Candidate premium = config max × leverage (financial-need satisfaction + score margin over the applicant pool) × learned factor; employer accepts at ask when premium ≤ learned cap **and** the S04 wage-reserve solvency rule holds; otherwise counters at cap; candidate accepts a counter at/above their reservation floor, else walks away. Every round is a persisted `negotiation_offers` row; both sides learn from the outcome within bounds. Wired into S04 `match_vacancies` for business vacancies only (civic/government pay is a fixed scale, never negotiated; worlds without the layer keep exact S04 behaviour). **Scoped down, honestly:** buyer/seller *price* negotiation was **not** built — S04 prices are per city+good, not per seller, so there is no per-seller price to negotiate without breaking the pricing machinery. What the supply pool does support — **supplier selection** — was upgraded instead: executed orders are recorded (`supply_orders`), and supplier ranking gains a measured-reliability term (trailing-3-month delivered units) active only when the layer is live.
7. **Business decision records** — every executed supply order writes an `agent_decisions` explanation (inputs → rule → outcome); negotiation decisions likewise.
8. **Assessments** — monthly per city: housing vacancy, road condition, unemployment, pollution, disaster recovery measured against configured thresholds → `identified`; the funded action an existing engine took is linked (S05 policy / S03 construction project / enacted `emission_limit` law / coordination record) → `acted`; the same indicator is re-measured a month later → `evaluated` with improved/not. Pollution raises a `recommendation` message to the government agent (the layer recommends; S05 decides).
9. **Coordination** — per disaster, tasks (assess → evacuate → shelter → relief → medical → repair) derived from S08's impacts; completion is proven by S08's own response records; overdue > 7 days escalates to the government agent by message (attempts recorded); tasks unmet at recovery close as `closed_unmet` with a failed action and a `review` task listing them — failure recorded and reviewed, never silently dropped.
10. **Forecasts** — transparent trend models (population from recorded births−deaths, housing vacancy, congestion from S07 statistics, business profit), each stored with its inputs and model description, then **scored** when the horizon arrives (abs/pct error recorded; forecast ≠ outcome, both kept).
11. **Orchestration** — engine hooks: registry sync at generation; daily coordination only when a disaster is live/recent; monthly pass last in the month (registry → memory → goals → forecasts → coordination → assessments), each reading the settled month. Conflict resolution: labour contention closure + the S02 household rule, both recorded.
12. **Observatory** — `python -m tools.sim --agents <db>`: registry, goals + progress log, negotiations + offers, decisions, forecasts with scores, assessments, coordination tasks, memories by level, learning, failed actions, messages.

## Honest limitations

- **Negotiation frequency is organic, and low by construction.** Zero negotiations occurred in the 65-day smoke (pop 60), the 180-day acceptance world (pop 100), the 210-day scenario (pop 100) and the 242×90 benchmark. The reason is measured, not a defect: leverage comes from the candidate's financial-need satisfaction and their score margin over the applicant pool — in a large pool the best candidate rarely stands out enough, and unemployed candidates rarely have the savings to hold out, so the premium stays below the 0.03 threshold and hiring proceeds at the posted wage (exact S04 behaviour). The protocol is proven three ways: direct unit tests (ask/counter/walk-away + learning changing the outcome), a labour-match integration test, and an in-world construction inside the acceptance test. Whether the threshold *should* be lower is a tuning question for the owner; the layer never manufactures negotiations to fill its own tables. Assessments behaved the same way until they didn't: empty in short runs, the full loop fired organically in the 210-day scenario.
- **Supplier price negotiation does not exist** (see Unit 6): S04 prices are per city+good. Reliability ranking is the honest signal the pool supports.
- **Learning is parameter adaptation only** — bounded numeric parameters with a recorded reason per change. No agent modifies code, rules, or its own capability set; capabilities change only by editing config.
- **The assessment loop links actions; it does not take them** (coordination excepted, which is this layer's own machinery). If no engine funds a response, an assessment stays `identified` — that is the record working as intended, not a gap to paper over.
- **Memory is records, not narrative.** Levels store structured event summaries with importance scores; there is no free-text recall and no claim of human-like memory.
- **Forecasts are labelled trend extrapolations** over recorded series — useful for testing the score-keeping loop, not predictions about any real place.
